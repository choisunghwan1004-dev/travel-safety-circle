# V1.6 무료 서비스와 선택형 본인 부담 AI

## 사용자 흐름
로그인 후 같은 계정·기기의 최초 안내 팝업 또는 상단 AI 설정 → 무료 기본 기능/AI 비용 설명 → 공식 OpenAI 키 발급 화면 → 본인 키 입력 → 본인 소유·비용 부담·암호화 보관 동의 → 등록 → 원래 화면으로 복귀. 탑승권/신고자료 화면에서도 AI 설정을 열 수 있으며 작성 중 여행 입력은 유지한다.

기본 기능은 키 없이 사용한다. 사진 인식·정리·번역은 선택 기능이다. API 비용은 키 소유자의 OpenAI 계정·프로젝트로 청구되며 ChatGPT 구독료와 별도다. 여행안심은 별도 이용료를 받지 않는다. 키 미등록·오류·잔액/권한 부족 시 AI만 제한된다. 서비스는 예방과 대비를 돕지만 실제 사고 예방·구조·기관 신고를 보장하지 않는다. 기존 문자·이메일 실발송과 무인 감시는 여전히 미연결이다.

## 키 처리
- POST /api/ai-key: 본인 인증, 동일 Origin, 본문 제한, sk- 형식 검사, 비용·보관 동의. 암호화 저장 후 끝4자리·등록시각만 응답한다. 실제 API 유효성·잔액·모델 접근은 첫 사용 시 검증되며, 저장 자체가 검증 성공을 뜻하지 않는다.
- GET /api/ai-key: 본인 상태·끝4자리·시각만 반환. POST action delete로 본인 키를 삭제한다. OpenAI에서 키 자체를 폐기하는 행위는 별도다.
- user_ai_keys: owner TEXT PK, ciphertext TEXT NOT NULL, iv TEXT NOT NULL, last_four TEXT NOT NULL, updated_at TEXT NOT NULL. 물리 FK 없음.
- AES-256-GCM, 매 저장마다 무작위 12바이트 IV, 계정 ID를 AAD에 결합한다. 계정 혼용·암호문 변조·다른 마스터키의 복호화는 실패한다.
- 마스터키 USER_KEY_ENCRYPTION_SECRET은 소스/DB/브라우저와 별도인 Sites 서버 비밀값으로 관리한다. 실제 비밀값은 저장소나 문서에 쓰지 않는다. 보안 운영자 권한은 여전히 신뢰 경계다. 운영 DB 백업의 과거 암호문 보관까지 즉시 제거하는 기능은 아니다.
- 브라우저는 키 입력 중 메모리에만 두고 저장 후 비운다. localStorage에는 계정별 안내 팝업을 본 표시만 둔다. 다른 서버·화면에 전체 키를 재전달하지 않는다.
- 요약/사진 인식 API는 로그인한 본인의 키만 읽으며 운영자 공용 OPENAI_API_KEY로 대체하지 않는다. 키가 없으면 503과 본인 설정 안내. 자동 AI 호출 없음.
- 기존 1분1회·UTC 하루20회 제한은 유지한다. 원화 총비용 상한을 보장하지 않으므로 본인 OpenAI 프로젝트 사용량과 비용 설정을 확인한다.
- 전체 자료 삭제에 저장 키 삭제도 포함한다. 이미 실행 중인 요청은 삭제 후 완료/청구될 수 있다.

## 배포와 로컬
서버 마스터키를 보안 환경변수로 구성한 뒤 배포한다. 로컬은 .dev.vars의 USER_KEY_ENCRYPTION_SECRET을 사용하고 사용자 API 키는 화면에서 등록한다. 키 값은 예시 파일에 넣지 않는다. 마스터키 회전/분실 시 기존 자료 복구 또는 사용자 키 재등록 계획이 필요하다. 새 0004 마이그레이션과 Drizzle snapshot은 user_ai_keys 테이블만 추가한다.

## 검증
AES-GCM 정상 복호화·무작위 IV·계정 분리·잘못된 마스터키·변조 차단·형식 검사 테스트. 전체 5개 마이그레이션 SQLite 순차 적용. TypeScript·production build 및 기존 규칙 테스트. 내부 브라우저에서 무료/비용 설명·키 없이 이용·마스킹 입력란 확인.
실제 사용자 키를 사용한 OpenAI 호출이나 결제·잔액 확인은 수행하지 않았다. 사용자 키는 키 보관 기능 배포 이후 본인이 직접 등록한다.
