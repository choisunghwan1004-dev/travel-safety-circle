# 여행안심 · 지침서에 맞춘 후속 개발 프롬프트

드론·날씨·뉴스·샘플 기사 예시는 넣지 않았습니다. 기존 React/Vinext/D1/R2 구현을 유지하며, 사용자 사진·위치·연락처 실제 값을 코드나 프롬프트에 넣지 않습니다.

## 공통 지시

여행안심 V1.8.1의 현재 README와 docs/13 최신 기준와 관련 소스를 먼저 읽어 주세요. 기존 UI·컴포넌트·State·스타일·동작을 생략하지 마세요. 원인과 수정 계획을 먼저 설명하고 기능 하나만 최소 변경해 주세요. 확인된 사실과 미검증을 구분하며, 실행·테스트 근거를 README에 남기고 작업 단위별로 커밋해 주세요. API 키·비밀번호·연락처·사진·정밀 위치 원본은 커밋하지 마세요.

## 1. 설계 검토

지금은 코드를 수정하지 말고 여행안심의 요구사항과 현재 구현 차이를 정리해 주세요. 기능정의서(ID·기능·입력→출력·구현 상태), 화면·이동 순서, 실제 DB의 테이블·컬럼·PK·물리 FK 유무, 데이터 출처, 개발환경을 작성해 주세요. D1의 JSON 내부 항목을 구현된 정규화 SQL 테이블로 표시하지 마세요.

## 2. README 커밋

검토한 설계를 프로젝트 소개, 기능정의서, 화면구성도, DB/ERD, 데이터 수집, 개발환경, 실행방법, 테스트의 8개 목차로 작성해 주세요. 등록 지인 전원의 이름·전화번호·이메일·수신동의 필수, 여행 중 2시간 위치 저장, 여행 시작과 마지막 안전 확인 중 늦은 시각부터 24시간 규칙, 귀가 완료 시 중지, 저장 후 메인 복귀를 포함해 주세요. 발송 키 미등록·정기 작업 일시 중지·실제 도착 미검증과 잠금 중 GPS 보장 불가라는 점을 먼저 표시하고 `docs: 여행안심 설계와 실행 안내 작성`으로 커밋해 주세요.

## 3. 기능별 개발·검증

이번 작업에서는 문자·이메일 발송서비스 연결만 다뤄 주세요. 기존 규칙·UI·DB는 유지하고, 개인 발송 설정은 화면에서 동의 후 암호화 보관하고 서버 마스터키와 분리하세요. 업체 공식 API를 확인하고 이름·전화·이메일·동의가 갖춰진 등록 지인 전원을 관계·인원 제한 없이 선택해 주세요. 본인이 지정한 시험 수신처로 검증하기 전 실수신 성공을 기록하지 마세요. API 요청 접수와 실제 수신을 구분하고, 실패·중복·통신 결과불명을 검사한 후 README 테스트 결과를 갱신해 커밋해 주세요.

## 4. 무인 감시 연결

앞 단계의 발송 시험이 통과한 뒤 Site MCP의 본인 계정 권한과 무인 실행 경로를 확인해 주세요. 24시간 미응답 여부를 주기적으로 검사하는 작업을 연결하고, 호출·저장내역을 실제로 확인하세요. 위치 저장이 안전 확인 시각을 초기화하지 않는지 확인하고 귀가 완료·알림 중지·연락처 삭제·이미 처리된 주기에 대해서는 보내지 마세요. 연결이 안 됐다면 완료라고 쓰지 마세요.

## 5. 운영 검수

여행·이름·연락처 정확성, 마지막 위치 확인시각과 오차, 사진 업로드시각, 수신 동의와 대상자, 발송 계정 및 실제 수신 시험, 귀가 완료 동작을 대조표로 확인해 주세요. 미응답을 실종 확정으로 표현하거나 경찰·대사관 접수 완료로 표현하지 마세요. 실제 iPhone/Android 잠금·종료 중 위치 추적은 별도 네이티브 개발이므로 웹 테스트 통과로 대신하지 마세요.
