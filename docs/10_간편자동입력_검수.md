# V1.5 간편 자동 입력·선택 흐름 검수

2026-10-21. 기존 화면·상태와 등록 후 메인 복귀를 유지하고 여행 등록 폼의 입력을 보조한다. 외부 API 성공이나 실기기 인식 품질은 코드 검사와 구분한다.

| 단계 | 자동·선택 처리 | 확인/직접 입력 |
|---|---|---|
| 여행자 | 인증 계정에 실명이 제공되면 빈 이름에 사용 | 별명·탑승권 이름 차이 확인, 본인 전화 |
| 국가/교통 | 국가 선택 또는 직접 행선지, 항공/기차/버스/자동차/배/도보/기타 | 실제 도시·숙소 |
| 사진 | 카메라/사진 선택, 긴 변 2000px JPEG 변환, 동의 후 OpenAI 읽기 | HEIC 등 브라우저가 못 여는 파일은 JPEG로 재선택 |
| 항공권 | 편명, 항공사, 출도착 공항, 날짜·현지 시각, 좌석, 게이트, 표기 이름 | 연도가 없으면 날짜 추정 안 함, 여러 구간은 첫 구간만, 귀가일 추정 안 함 |
| 자동 채우기 | 기존 값은 보존하고 빈 항목만 채움. 계정·탑승권·선택 이동수단 재사용 | 모든 필드 수정 가능 |
| 날짜 | 당일/1박2일/2박3일/3박4일/6박7일 선택 → 귀가일 계산 | 여행 종료일이 비행 도착일과 같다고 단정 안 함 |
| 안전 확인 | 기본 12시간, 6/12/24시간 빠른 선택, 미래 여행은 출발일부터 계산 | 기기의 현지시각 기준, 24시간 미응답 규칙 자체는 기존 유지 |
| 위치 | 마지막 저장 좌표 사용 또는 GPS 권한 후 현재 좌표 취득 | 현재 위치 버튼으로 얻은 좌표는 최종 여행 저장 시 함께 저장 |
| 집 지역 | ‘현재 위치를 집 지역으로’ 명시 선택 또는 시·구·동 입력 | 현재 위치를 자동으로 집으로 간주하지 않음, 상세주소 외부 전송 안 함 |
| 경찰서 | OpenStreetMap 지역 중심 15km 후보, 직선거리 순 5개, 선택 시 이름/주소/전화 채움 | 자료 누락 시 번호 공란. 관할·최인접 보장 안 함. 기존 값 변경 시 확인 |
| 마지막 지역 | 마지막/현재 좌표의 행정지역과 해당 위치 확인시각 입력 | 현재·실종 추정·마지막 저장 위치를 구분. 저장 지역은 최신 GPS와 시점이 다를 수 있음 |
| 연락망 | 기존 관계 선택·전화·이메일 검증·중복 검사 유지 | 연락처 수신동의 및 이름/전화/이메일 필수. 전체 전화번호부 임의 수집 안 함 |
| 사진/신고자료 | 기존 업로드·서버 시각·자료 공유·PDF 유지, 항공/지역/경찰 필드 추가 | 기관 자동 신고 아님 |
| 저장 | 동일 Origin·본인 인증·revision 확인, 올바른 달력 날짜/GPS 검사 후 저장 → 홈 | 오래되거나 미래인 GPS 차단. 수동 GPS는 자동 저장 간격을 재설정하지 않음 |

## 서버와 DB
- `/api/flight`: JPEG 데이터만, 요청 본문 최대 2.2MB, 전송 동의, 서버 키. OpenAI Responses API gpt-6-luna, store:false, 엄격한 JSON, 60초 제한. 이미지 URL을 사용자에게 받지 않아 외부 URL 임의 조회 없음. 바코드·예약/여권/결제번호는 출력 대상으로 삼지 않는다. 입력 사진 자체에 보일 수 있으므로 촬영 전에 가리도록 안내한다.
- 사진 원본·AI 결과는 별도로 DB/R2에 저장하지 않는다. 확인 후 저장한 구조화 여행 필드만 기존 journeys.data에 들어간다.
- AI 요청은 기존 ai_usage의 계정별 요약과 합산하여 1분 1회, UTC 하루 20회. 키는 추후 입력한다.
- `/api/police`: 동의한 지역 또는 약 1km 단위 좌표만 Nominatim과 Overpass로 보낸다. 이름·전화·계정 ID·상세 집주소 필드는 보내지 않는다. 공개 서비스이므로 누락·응답 지연이 있을 수 있다.
- 지도 요청: 개인별 10초 1회/UTC 하루30회. 서버 전체 캐시 미스 요청은 1.5초 간격/하루1000회로 제한. 자동완성 입력마다 호출하거나 정기 GPS마다 호출하지 않는다.
- lookup_cache: id TEXT PK(검색어 해시), data TEXT(공개 지역과 경찰시설), expires_at INTEGER. 24시간 캐시, 만료 자료는 성공 검색 시 정리하며 만료 캐시는 사용하지 않는다. 물리 FK 없음.
- 기존 0002에 AI 제한 테이블이 있어, 생성한 0003 SQL에서 중복 AI 테이블 생성 부분만 제외했다. 0003 snapshot에는 4개 테이블을 반영하여 후속 생성 기준을 맞췄다. 기존 적용 마이그레이션은 수정하지 않았다.
- GEOCODER_BASE_URL / OVERPASS_API_URL은 서버 설정으로 교체 가능하다. 기본값은 공개 Nominatim/Overpass이며 별도 지도 키는 필요 없다. 운영 규모 증가 시 별도 제공자 전환이 필요하다.

## 검증
- 타입 검사, 규칙 테스트: 기존값 보존·날짜/시간 형식·잘못된 일자·연말 귀가일 계산·오래된/미래/범위 밖 GPS·경찰서 좌표/거리 정렬·전화 누락 처리.
- SQLite로 0000~0003 마이그레이션 전체 순차 실행 확인.
- 내부 브라우저: 선택 메뉴·이동수단 자동 채우기·귀가일 2026-12-31 +2박 → 2027-01-02 확인. 날짜 input 이벤트 반영 문제 수정.
- 미검증: 실제 사용자 탑승권 OpenAI 인식(키 미설정), 실제 iPhone 카메라/HEIC/GPS, 각 지역 경찰번호·관할의 정확성. 모의 자료/규칙 검사를 실제 인식 성공으로 표현하지 않는다.
